## Vue3源码解析（二）：调度系统、Diff与patch流程

> 上一篇源码解析更偏响应式和编译优化。这篇补上面试里也很常追问的另一半：状态变化之后，更新是怎么被调度的，虚拟节点又是怎么 Diff 和 patch 到真实 DOM 的。

<!-- more -->

## 一、响应式触发之后，更新为什么不是立刻同步改 DOM？

因为 Vue 会做异步批处理。

同一轮事件循环里，如果多个响应式数据连续变化，Vue 通常不会每改一次就立刻重渲染一次，而是：

1. 收集本轮需要执行的副作用
2. 放入调度队列
3. 在合适的时机统一 flush

这样做的好处：

+ 减少重复渲染
+ 合并多次更新
+ 保证 DOM 更新时机可控

## 二、调度系统可以怎么理解？

可以把它理解成：

> 响应式系统负责发现“谁该更新”，调度系统负责决定“什么时候更新”。

常见概念：

+ `job`：一个待执行的更新任务
+ 队列：用来缓存本轮任务
+ `flushJobs`：统一执行队列里的任务

## 三、`nextTick` 和调度队列有什么关系？

`nextTick` 之所以能“等 DOM 更新后执行”，就是因为它和调度刷新落在同一套异步时机附近。

粗略理解：

+ 状态变更触发 job 入队
+ 队列在微任务阶段 flush
+ `nextTick` 回调也会排到更新之后

所以它不是魔法延时，而是更新时序 API。

## 四、组件更新的主链路是什么？

可以按这条链路回答：

1. 修改响应式数据
2. `trigger` 触发依赖
3. 组件渲染 effect 进入调度队列
4. flush 时重新执行 render
5. 生成新的 vnode
6. 和旧 vnode 做 patch
7. 把差异提交到真实 DOM

## 五、`patch` 是什么？

`patch` 是把新旧虚拟节点差异同步到真实 DOM 的过程。

它会判断：

+ 是否是相同类型节点
+ 要不要复用 DOM
+ 属性和事件怎么更新
+ 子节点怎么 Diff
+ 要不要卸载旧节点

## 六、Vue3 Diff 的大致思路是什么？

面试里不要只背“用了最长递增子序列”，最好按层次说。

### 1. 先走快速路径

比如：

+ 前置相同节点可快速处理
+ 后置相同节点可快速处理
+ 纯新增、纯删除有特判

### 2. 再处理复杂中间部分

当头尾快速路径走完后，中间乱序部分会进入更复杂的处理。

### 3. 用最长递增子序列减少移动

目标是：

+ 尽量复用已有节点
+ 尽量让“原本相对顺序正确的节点”不动
+ 只移动真正需要移动的节点

## 七、为什么列表 `key` 在 Diff 里这么重要？

因为 Diff 需要知道：

+ 新旧子节点里，谁是同一个节点

没有稳定 `key`：

+ 复用容易出错
+ 移动成本可能变高
+ 组件状态可能错位

有稳定 `key`：

+ 新旧映射更准确
+ patch 更高效

## 八、静态标记如何影响 patch？

编译期打上的 `Patch Flag`，会在运行时告诉 patch：

+ 这个节点也许只需要更新文本
+ 也许只需要更新 class
+ 也许只需要更新某几个 props

于是更新时不必每次都做全量属性对比。

这就是“编译优化反哺运行时 patch”的关键点。

## 九、卸载流程为什么也要理解？

更新不只是“改”和“增”，还有“删”。

卸载时通常要做：

+ 移除真实 DOM
+ 清理组件副作用
+ 停止相关 `watch` / 渲染 effect
+ 触发卸载生命周期

这也是为什么组件里定时器、事件监听一定要在合适时机清理。

## 十、`mounted`、`updated`、`unmounted` 和 patch 的关系？

可以粗略对应：

+ 首次 patch 完成 → 挂载相关钩子
+ 后续 patch 完成 → 更新相关钩子
+ 节点移除完成 → 卸载相关钩子

所以生命周期不是孤立概念，而是渲染和 patch 流程上的观测点。

## 十一、Vue3 源码题怎么答才完整？

建议两篇合起来记：

### 响应式篇

+ `Proxy`
+ `track` / `trigger`
+ `effect`
+ `computed` / `watch`

### 更新篇

+ 调度队列
+ `nextTick`
+ render
+ Diff / patch
+ 生命周期触发时机

完整一句话：

> Vue3 先靠响应式发现变化，再靠调度合并更新，最后靠 Diff 和 patch 把最小必要变更落到 DOM。

## 十二、一段适合面试现场的总结话术

> Vue3 的更新链路可以概括成：响应式系统通过 `track/trigger` 发现依赖变化，调度系统把更新任务放入队列并异步批处理，随后组件重新执行 render 生成新的 vnode，再通过 Diff 和 patch 把差异应用到真实 DOM。其中 `key`、`Patch Flag`、最长递增子序列这些点，决定了列表更新和属性更新能不能足够精准。理解了这条链路，`nextTick`、生命周期时机、性能优化很多题就都能串起来了。
